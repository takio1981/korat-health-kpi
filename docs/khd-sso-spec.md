# สเปกการเข้าสู่ระบบอัตโนมัติจาก KHD → KHUPS KPI

สำหรับผู้พัฒนาระบบ KHD (khd.moph.go.th) — เพิ่มลิงก์ที่พาผู้ใช้เข้า KHUPS KPI ได้ทันทีโดยไม่ต้องกรอกรหัสผ่านอีก

## ภาพรวม
1. ผู้ใช้ที่เข้าสู่ระบบ KHD แล้วกดลิงก์ "เข้า KHUPS KPI"
2. ฝั่งเซิร์ฟเวอร์ของ KHD สร้าง JWT อายุสั้น (ลงนาม HS256 ด้วยรหัสลับร่วม) แล้วส่งผู้ใช้ไปที่
   `https://apikorat.moph.go.th/khupskpi/login?khd_token=<JWT>`
3. KHUPS KPI ตรวจลายเซ็นและเงื่อนไข แล้วเข้าสู่ระบบให้ทันที
   - ไม่ผ่าน: แจ้งเหตุผล และให้ผู้ใช้กรอกชื่อผู้ใช้/รหัสผ่านเอง
   - บัญชีกำลังใช้งานอยู่ที่เครื่องอื่น: ถามผู้ใช้ก่อนว่าจะเข้าใช้ที่เครื่องนี้หรือไม่

> URL ทั้ง 2 ตัว (URL ระบบ KHD และ URL หน้าเข้าสู่ระบบของ KHUPS KPI) ผู้ดูแลระบบ KHUPS เปลี่ยนได้ที่ ตั้งค่าระบบ → "เข้าสู่ระบบอัตโนมัติจาก KHD"
> ถ้าเปลี่ยน ผู้ดูแลระบบ KHUPS จะแจ้งค่าใหม่ให้ทีม KHD

## JWT ที่ต้องส่ง
| ส่วน | ค่า |
|---|---|
| algorithm | `HS256` เท่านั้น (ห้าม `none` / RS256) |
| รหัสลับ | ผู้ดูแลระบบ KHUPS สร้างในหน้าตั้งค่า แล้วส่งให้ทีม KHD ทางช่องทางที่ปลอดภัย<br>ห้ามเก็บไว้ในโค้ดฝั่งเบราว์เซอร์ หรือใน repository |
| `username` | ชื่อผู้ใช้ของบัญชี ต้องตรงกับบัญชีใน KHUPS KPI ใช้ `sub` แทนได้ |
| `iat` | เวลาที่สร้าง (วินาที, Unix time) |
| `exp` | เวลาหมดอายุ ต้องไม่เกิน `iat + 300` (5 นาที) |
| `jti` | ค่าสุ่มที่ไม่ซ้ำกันทุกครั้ง เช่น UUID ใช้ได้ครั้งเดียว |
| `iss` | ชื่อโฮสต์ของ URL ระบบ KHD ที่ตั้งไว้ (ค่าตั้งต้น `khd.moph.go.th`) หรือค่าที่ผู้ดูแลตั้งเอง |
| `aud` | `khupskpi` (ค่าตั้งต้น) |

- **ห้ามใส่รหัสผ่าน เลขบัตรประชาชน หรือข้อมูลส่วนบุคคลอื่นใน JWT** เพราะเนื้อหา JWT อ่านได้โดยไม่ต้องใช้รหัสลับ
- ให้สร้าง token **ฝั่งเซิร์ฟเวอร์ทุกครั้งที่ผู้ใช้กดลิงก์** ห้ามสร้างล่วงหน้าแล้วฝังไว้ในหน้าเว็บ (อายุลิงก์ 5 นาที)
- ส่งผู้ใช้ไปด้วย redirect (302) หรือเปิดลิงก์ในแท็บใหม่ ห้ามส่ง token ผ่านช่องทางอื่น

## ตัวอย่าง: PHP (firebase/php-jwt)
```php
use Firebase\JWT\JWT;
$now = time();
$token = JWT::encode([
    'username' => $currentUser['username'],
    'iat' => $now,
    'exp' => $now + 120,
    'jti' => bin2hex(random_bytes(16)),
    'iss' => 'khd.moph.go.th',
    'aud' => 'khupskpi',
], getenv('KHUPS_SSO_SECRET'), 'HS256');
header('Location: https://apikorat.moph.go.th/khupskpi/login?khd_token=' . urlencode($token));
exit;
```

## ตัวอย่าง: Node.js (jsonwebtoken)
```js
const jwt = require('jsonwebtoken');
const crypto = require('crypto');
const token = jwt.sign(
  { username: req.user.username, jti: crypto.randomUUID() },
  process.env.KHUPS_SSO_SECRET,
  { algorithm: 'HS256', expiresIn: 120, issuer: 'khd.moph.go.th', audience: 'khupskpi' }
);
res.redirect('https://apikorat.moph.go.th/khupskpi/login?khd_token=' + encodeURIComponent(token));
```

## ผลการตรวจฝั่ง KHUPS KPI
| กรณี | ผล |
|---|---|
| token ถูกต้อง, บัญชีเปิดใช้งานและอนุมัติแล้ว | เข้าสู่ระบบ ไปหน้าบันทึกผลงาน |
| ลายเซ็นผิด / หมดอายุ / อายุเกิน 5 นาที / ไม่มี `jti` / `iss` หรือ `aud` ไม่ตรง / ใช้ token ซ้ำ | ไม่เข้าสู่ระบบ ให้ผู้ใช้กรอกรหัสผ่านเอง |
| ไม่พบชื่อผู้ใช้ใน KHUPS KPI | แจ้ง "ไม่พบบัญชี" ให้ลงทะเบียนหรือติดต่อผู้ดูแล |
| บัญชีปิดใช้งาน / รออนุมัติ / ถูกปฏิเสธ | แจ้งตามสถานะ (กติกาเดียวกับการเข้าสู่ระบบด้วยรหัสผ่าน) |
| บัญชีกำลังใช้งานที่เครื่องอื่น | ถามผู้ใช้ก่อน ยืนยันแล้วเครื่องเดิมออกจากระบบ |
| ผู้ดูแลยังไม่เปิดใช้ / ยังไม่สร้างรหัสลับ | ไม่เข้าสู่ระบบ ให้ผู้ใช้กรอกรหัสผ่านเอง |

ทุกครั้งที่เข้าสู่ระบบจาก KHD จะบันทึกลงประวัติการเข้าสู่ระบบว่า "เข้าสู่ระบบจาก KHD"
